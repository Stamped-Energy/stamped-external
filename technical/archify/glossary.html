Glossary

Plain-English terms for cross-layer docs (61 terms). Back to start

Stamped
[all] the product. It turns plant data into one decision card per issue, with one owner. (The company is Stamped Energy; the product is just "Stamped".) See: SYS-00
Five domains
[all] the kinds of value a card can be about: Energy, Cost, Time/throughput, Continuity/flow, Exception. See: SYS-00
Operating loop
[all] detect (L3) → recommend (L4) → assign → act → verify (L5, people via L6) → learn (designed). See: SYS-05
Card
[L4/L5] one decision for one owner. It starts as an immutable *card proposal* from L4 and becomes a *live card* tracked by L5. See: SYS-06
Evidence tiers
[L3/L4] how strong a claim is: Measured, Confirmed, Modeled, Unknown (L4 also uses Advisory). Code assigns the tier, not the model. See: SYS-01
Edge-agent
[L1] Go program at the plant that reads machines and meters through protocol adapters. It is read-only toward plant equipment and has no inbound network port. See: SYS-01
Context-agent
[L1] companion program on the plant's IT network that reads business data (orders, shifts) from files, REST or SQL and publishes context records. See: SYS-01
Tag mapping / value_map
[L1] rules that turn a raw device tag into a named Stamped measurement with units. Mappings are signed and shipped over the air. See: SYS-01
Store-and-forward buffer
[L1] local SQLite queue (about 72 hours) that keeps readings while the uplink is down and sends them when it returns. See: SYS-01
MQTT QoS 1
[L1] the messaging protocol and delivery level used to publish batches: "at least once", so duplicates are possible and are removed later. See: SYS-01
Envelope
[L1/L2] the standard wrapper around every record (who, where, what type, when, content hash) defined in the contracts. See: SYS-01
Outbox / relay
[L1/L3/L5] a reliability pattern. Write the outgoing message into a database table in the same transaction as the work, then a separate relay process sends it and retries until acknowledged. See: SYS-01
DLQ (dead-letter queue)
[L1] where invalid messages go (`l1_dlq`) so they are kept for inspection instead of silently dropped. See: SYS-01
Dedupe hash
[L1/L2] SHA-256 fingerprint of a record used to drop exact duplicates. See: SYS-01
Context record
[L1/L2] a piece of business context (e.g. production order, shift) stored alongside telemetry so detections can be explained. See: SYS-01
Bill validation (±₹1)
[L1] a bill's extracted fields are recomputed and must match the printed total within one rupee, and a human reviews it, before it may be published. See: SYS-01
Universal repository
[L2] the central TimescaleDB-backed store with seven schemas (ingest, telemetry, graph, commercial, features, baselines, ledger) plus context tables. See: per-repo L2-01
Ingest vs query-api
[L2] ingest is the only write door; query-api is the read door used by L3, L4, L5 and L6. See: SYS-01
RLS / X-Org-Id
[L2] row-level security. Every read carries the customer organisation id, and the database only returns that organisation's rows. See: SYS-01
Agent-tools catalog
[L2] the list of read tools L4 is allowed to call (no raw SQL, no organisation argument, no free graph traversal). See: SYS-01
Finding
[L3] a detected, evidenced problem or opportunity at a plant (versioned contract; 1.2.0 by default, 2.0.0 behind a flag). See: per-repo L3C-02a
Detection run
[L3] one execution of the detection pipeline for one plant and window, started on demand (API/CLI). Only one active run per plant. See: SYS-01
Engine / rule
[L3] engines compute signals (idle, maximum demand, power factor, energy per unit…). Rules from rulepacks decide when a signal becomes a Finding. See: SYS-01
Rulepack
[L3] versioned rule files merged domain → vertical → plant → tariff. Findings cite the exact rule as `rulepack://pack/version#rule`. See: SYS-01
Gates
[L3] automatic quality checks (e.g. g14, precision, PSI drift) a Finding must pass. See: SYS-01
Lane: l4 vs lab_only
[L3] emitted Findings go to L4; suppressed, shadow-only or hypothesis Findings stay in the Lab. See: SYS-01
Condition key
[L3/L4] a fingerprint of plant + family + assets + window start, used to recognise the same condition and avoid duplicate work. See: SYS-01
Certification / shadow
[L3] a claim that fails certification is kept "in shadow" (recorded, not sent onward). The check fails closed. See: SYS-01
Calculator / calculator_ref
[L3] the only component allowed to compute rupee amounts. Others must cite its result by reference. See: SYS-01
Methods API (MCP)
[L3] service on port 8094 that lets L4 ask L3 for condition tests, calculations, verification plans and simulations. It requires a service key. See: SYS-01
Evals / Lab
[L3] backtests and gates (e.g. precision ≥ 0.75) that decide whether detection changes are good. The Lab never promotes anything to L4 by itself. See: SYS-01
Decision runtime
[L4] the worker that turns one emitted Finding into a decision through a fixed stage graph. See: per-repo L4-02
DecisionCase
[L4] the unit of work for one condition, with states (queued, leased, running, …, terminal). See: SYS-01
Stage graph
[L4] candidates → constraints → portfolio → minimizer → kernel_recheck → terminal. Only *candidates* calls a language model; the rest is code. See: SYS-01
Seam / port
[L4] the controlled doorway through which a stage calls a model or tool (e.g. `seams.draft`). See: SYS-01
Dual-family
[L4] drafts from two different model families are compared and resolved in code before being trusted. Tests use a fixture model by default. See: SYS-01
PSM (plant state model)
[L4] L4's structured picture of the plant (structure, snapshot, digest, propagation) used to build context. See: SYS-01
Context assembly
[L4] the ordered process that gathers facts (Finding, PSM, L2 tools, L3 methods, registry prompts) into a typed fact ledger and a prompt. See: SYS-01
Terminal outcomes
[L4] emit, supersede, withhold or abstain. A DecisionTrace is always written. See: SYS-01
DecisionTrace
[L4] the audit record of how a decision was reached. See: SYS-01
can_emit / kill switch / shadow_only
[L4] guards that must all allow it before a card proposal leaves L4. The default sink is a stub. See: SYS-01
BudgetMeter
[L4] hard caps on model calls, tokens and cost. See: SYS-01
Ask analyst (ReAct)
[L4] the question-answering agent. It loops "think → call a tool → read result" until it answers or abstains, within a turn budget. See: SYS-01
RRF (reciprocal rank fusion)
[L4] a way to merge ranked results from several retrieval sources into one list. See: SYS-01
Hindsight memory
[L4] long-term learning memory described in docs. **DESIGNED only, not built.** See: SYS-01
Live card workflow
[L5] the states a card moves through (open, in progress, done, deferred, rejected, disputed…). Some states are hidden from customers. See: SYS-01
ops_clearance / stabilize window
[L5] the condition and waiting period used to check, from data, that a fixed problem stays fixed. See: SYS-01
ops_confirmed vs verified
[L5/L6] ops_confirmed = cleared by operations data. "Verified" is reserved for the bill-based path, which is deferred. The UI must never blur them. See: SYS-01
Ledger (append-only)
[L5] record of realised value. Corrections add a new entry that supersedes the old one; nothing is overwritten. See: SYS-09
Webhook (HMAC)
[L5/L6] signed notification from L5 to the L6 backend when a card changes. See: SYS-01
BFF
[L6] backend-for-frontend. The server that sits between the browser and the other layers and keeps API keys off the browser. See: per-repo L6-02
Live vs Preview badge
[L6] shows whether a screen uses real upstream data or fixtures. See: SYS-01
SSOT / contracts
[platform] `stamped-external`, the single source of truth for decisions (ADRs) and versioned contracts that all layers follow. See: SYS-01
PathScheduler
[L3] Built scheduler service not started by deploy; port docs disagree 8093 vs 8094. See: SYS-01
HttpCardSink
[L4] Default outbound stub targeting POST /cards while L5 lacks that route. See: SYS-01
PlantWorkQueue
[L4] In-memory queue leasing DecisionCases per plant. See: SYS-01
clearance_poll
[L5] Worker loop reading L2 evidence to decide ops_confirmed vs disputed. See: SYS-01
sanitizeClaimStatus
[L6] UI guard keeping deferred bill-verified separate from ops_confirmed. See: SYS-01
Fleet precision gate
[L3E] Evals default 0.75 fleet gate vs 0.85 cited in docs. See: SYS-01
RELAY_TRANSPORT kafka
[L1C] Kafka relay publisher not implemented (HTTP only). See: SYS-01
CONTEXT_POLL_ENABLED
[L1] SaaS context poller defaults off with empty poll list. See: SYS-01
