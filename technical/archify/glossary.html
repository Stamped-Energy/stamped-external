Glossary

Plain-English terms for cross-layer docs (61 terms). Back to start

Stamped
[all] The product name is Stamped. See: SYS-00-stamped-end-to-end
Five domains
[all] the kinds of value a card can be about: Energy, Cost, Time/throughput, Continuity/flow, Exception. See: SYS-00-stamped-end-to-end
Operating loop
[all] detect (L3) → recommend (L4) → assign → act → verify (L5, people via L6) → learn (designed). See: SYS-05-operating-loop
Card
[L4/L5] one decision for one owner. It starts as an immutable card proposal from L4 and becomes a live card tracked by L5. See: SYS-06-condition-lifecycle
Evidence tiers
[L3/L4] how strong a claim is: Measured, Confirmed, Modeled, Unknown (L4 also uses Advisory). Code assigns the tier, not the model. See: SYS-09-money-lineage
Edge-agent
[L1] Go program at the plant that reads machines and meters through protocol adapters. It is read-only toward plant equipment and has no inbound network port. See: L1E-01
Context-agent
[L1] companion program on the plant IT network that reads business data (orders, shifts) from files, REST or SQL and publishes context records. See: L1E-04
Tag mapping / value_map
[L1] rules that turn a raw device tag into a named Stamped measurement with units. Mappings are signed and shipped over the air. See: L1E-03
Store-and-forward buffer
[L1] Local SQLite buffer: readings stay until MQTT QoS 1 publish is acknowledged, then marked sent; after an outage the backlog drains in batches; unsent readings are not expired by code (retention applies to already-sent rows only, and no prune loop runs on main). See: L1E-02
MQTT QoS 1
[L1] the messaging protocol and delivery level used to publish batches: at least once, so duplicates are possible and are removed later. See: L1E-02
Envelope
[L1/L2] the standard wrapper around every record (who, where, what type, when, content hash) defined in the contracts. See: SYS-01-contract-boundary-map
Outbox / relay
[L1/L3/L5] a reliability pattern. Write the outgoing message into a database table in the same transaction as the work, then a separate relay process sends it and retries until acknowledged. See: L1C-02
DLQ (dead-letter queue)
[L1] where invalid messages go (l1_dlq) so they are kept for inspection instead of silently dropped. See: L1C-01
Dedupe hash
[L1/L2] SHA-256 fingerprint of a record used to drop exact duplicates. See: L1C-03
Context record
[L1/L2] A piece of business context (e.g. production order, shift) stored alongside telemetry so detections can be explained. See: L1E-04
Bill validation (±₹1)
[L1] Lines must recompute within ±₹1 of the printed total; mismatches stay in review for human correction; passing bills are published (auto-publish when a publisher is configured); publish refuses unvalidated lines. See: L1B-02
Universal repository
[L2] the central TimescaleDB-backed store with seven schemas plus context tables. See: L2-01
Ingest vs query-api
[L2] ingest is the only write door; query-api is the read door used by L3, L4, L5 and L6. See: L2-02
RLS / X-Org-Id
[L2] row-level security. Every read carries the customer organisation id. See: L2-04
Agent-tools catalog
[L2] The list of read tools L4 is allowed to call (no raw SQL, no organisation argument, no free graph traversal). See: L2-04
Finding
[L3] a detected, evidenced problem or opportunity at a plant (Finding schema 1.2.0 by default). See: L3C-02a
Detection run
[L3] one execution of the detection pipeline for one plant and window, started on demand. See: L3C-02b
Engine / rule
[L3] engines compute signals; rules from rulepacks decide when a signal becomes a Finding. See: L3C-04
Rulepack
[L3] versioned rule files merged domain → vertical → plant → tariff. See: L3R-01
Gates
[L3] On the detection hot path the only per-Finding filter is suppression, then lane (emitted → L4 vs lab_only). g14 is on the cold baseline path; precision ≥ 0.75 and PSI are offline eval/CI gates in intelligence-evals — they never auto-promote to L4. See: SYS-05-operating-loop
Lane: l4 vs lab_only
[L3] emitted Findings go to L4; suppressed or shadow-only Findings stay in the Lab. See: L3C-08
Condition key
[L3/L4] a fingerprint of plant + family + assets + window start, used to recognise the same condition. See: L4-06
Certification / shadow
[L3] a claim that fails certification is kept in shadow (recorded, not sent onward). See: L3C-08
Calculator / calculator_ref
[L3] the only component allowed to compute rupee amounts. Others must cite its result by reference. See: L3C-06
Evals / Lab
[L3] backtests and gates (e.g. precision ≥ 0.75) that decide whether detection changes are good. See: L3E-02
Decision runtime
[L4] the worker that turns one emitted Finding into a decision through a fixed stage graph. See: L4-02
DecisionCase
[L4] the unit of work for one condition, with states (queued, leased, running, …, terminal). See: L4-06
StubCardSink
[L4] Default card sink: writes proposals locally, delivers nothing; emit_enabled=false and shadow_only=true by default. See: SYS-00-stamped-end-to-end
Stage graph
[L4] candidates → constraints → portfolio → minimizer → kernel_recheck → terminal. See: L4-03
Seam / port
[L4] the controlled doorway through which a stage calls a model or tool. See: L4-05
Dual-family
[L4] drafts from two different model families are compared and resolved in code. See: L4-05
PSM (plant state model)
[L4] L4 structured picture of the plant used to build context. See: L4-04
Context assembly
[L4] the ordered process that gathers facts into a typed fact ledger and a prompt. See: L4-04
Terminal outcomes
[L4] emit, supersede, withhold or abstain. A DecisionTrace is always written. See: L4-02
DecisionTrace
[L4] the audit record of how a decision was reached. See: L4-02
can_emit / kill switch / shadow_only
[L4] guards that must all allow it before a card proposal leaves L4. See: L4-09
BudgetMeter
[L4] hard caps on model calls, tokens and cost. See: L4-09
RRF (reciprocal rank fusion)
[L4] a way to merge ranked results from several retrieval sources into one list. See: L4-08
Hindsight memory
[L4] long-term learning memory described in docs. DESIGNED only, not built. See: L4-10
ops_clearance / stabilize window
[L5] the condition and waiting period used to check that a fixed problem stays fixed. See: L5-04
ops_confirmed vs verified
[L5/L6] Careful: L5 workflow state verified means ops-cleared (telemetry), not bill-verified; the UI demotes any verified claim without bill line references to ops_confirmed. Bill-verified remains deferred (ADR-020). See: SYS-04-closure-mv-runtime
Webhook (HMAC)
[L5/L6] DESIGNED: signed push from L5 to L6. As-built: L6 BFF polls L5 events every 30 s; no inbound webhook route on main. See: L6-04a
Live vs Preview badge
[L6] shows whether a screen uses real upstream data or fixtures. See: L6-02
HttpCardSink
[L4] Optional sink that would POST card proposals to L5 /cards (a route L5 does not have). Default on main is StubCardSink. See: SYS-02-data-batch-runtime
PlantWorkQueue
[L4] In-memory queue leasing DecisionCases per plant. See: L4-02
clearance_poll
[L5] Worker loop reading L2 evidence to decide ops_confirmed vs disputed. See: SYS-04-closure-mv-runtime
sanitizeClaimStatus
[L6] UI guard keeping deferred bill-verified separate from ops_confirmed. See: L6-05
Fleet precision gate
[L3E] Evals default 0.75 fleet gate vs 0.85 cited in docs. See: L3E-02
RELAY_TRANSPORT kafka
[L1C] RELAY_TRANSPORT=kafka publisher is not implemented (HTTP only). See: L1C-01
CONTEXT_POLL_ENABLED
[L1] SaaS context poller defaults off with empty poll list. See: SYS-08-built-vs-designed
Methods API (MCP)
[L3] Service on port 8094 (code default) that lets L4 call condition tests, calculations, verification plans and simulations; OpenAPI/docs may cite 8093. See: L3C-05
PathScheduler
[L3] Built scheduler service in intelligence-core; not started by default deploy (see docker-compose gap). See: L3C-03
Ask analyst (ReAct)
[L4/L6] (1) Retired today: every call returns 503 ASK_MOVED — Ask route retired (AskRetired); reason not documented beyond that. (2) ReAct loop (≤6 turns) is DESIGNED only. (3) 12 agent tools + retrieval are BUILT but not wired to live Ask (CLI remains). (4) UI: Analyst unavailable when L4_LIVE on; fixture + Preview chip when off. See: SYS-03-ask-runtime
Live card workflow
[L5] Wire WorkflowState values on main: blocked, pending_stamped_review, withheld, open, in_progress, done, verified, deferred, rejected, disputed (ten lowercase values; SSOT names differ). pending_stamped_review and withheld are staff-only (hidden from the customer) and are not among the SSOT eight. See: L5-03
Ledger (append-only)
[L5] record of realised value; append-only with supersedes. See: SYS-09-money-lineage
BFF
[L6] backend-for-frontend between browser and upstream layers. See: L6-02
SSOT / contracts
[platform] stamped-external contracts and ADRs. See: EXT-01
