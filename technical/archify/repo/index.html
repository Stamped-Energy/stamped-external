What this repo does at runtime

Nothing listens on a port here: the pack is read when layer repos mount external/ at build and CI time. A platform PR triggers contract-check.sh, which loads every JSON schema under contracts/schemas and validates golden fixtures. Maintainers tag semver releases; consumer repos bump their submodule pin (ADR-011). Vision and ADR markdown set product law; contracts/ sets wire bytes. Outputs are validated schemas, handoff docs, and green CI—not plant telemetry.

The diagrams, explained

EXT-01 — stamped-external SSOT pack

architecture · answers: authority map for the whole pack

The SSOT repo holds vision, ADRs, technical architecture, versioned contracts, handoffs, and CI scripts—there is no runtime service. Layer repos import it as external/ and run the same contract checks on every PR. Follow the top row for “what is authoritative”; the second row shows integration docs and the submodule bump after green CI. Everything is tagged BUILT because the markdown and schemas exist on main with tests.

Start with the guided view "Vision to contracts".

EXT-04 — Authority order

workflow · answers: precedence when two docs conflict

When internal docs disagree, read vision files first—founder vision 09 wins product meaning—then ADR-030 and STAMPED_ARCHITECTURE.md, then technical/l4/, then handoff, then wire schemas. Identity lint blocks withdrawn company framing on PRs. Prefer this chain over archived “compiler-only” L4 layer notes (gap G9).

Start with the guided view "Vision chain".

EXT-02 — Contract change

workflow · answers: schema change process

A schema change starts as a PR in this repo with CHANGELOG and optional ADR, runs contract-check.sh, merges, tags, and triggers submodule bump PRs in consumers. Dual-read windows (e.g. Finding 2.0.0 beside 1.2.0) are documented before deprecated shapes are dropped.

Start with the guided view "Propose and edit".

EXT-03 — Catalog dataflow

dataflow · answers: who produces and consumes each family

L1 publishes into envelope and related families; L3 emits Findings into intelligence/*; L2 ingests envelope-shaped rows; L4 runtime consumes Findings and emits card proposals under the same catalog. L5/L6 are readers of closure and intelligence DTOs defined here—not drawn as separate producers in this compact view.

Start with the guided view "L1 → L2 families".

EXT-05 — Version lifecycle

lifecycle · answers: draft → active → deprecated

Contract versions move from draft PR through CI review to active default on main; deprecated schemas stay dual-read while consumers catch up. A formal “removed” state is policy text in CHANGELOG only (DESIGNED—not automated in CI).

Start with the guided view "Draft to active".

Glossary (this repo)

SSOT / contracts
stamped-external is the single source of truth for ADRs and versioned wire schemas all layers import via submodule. (see EXT-01)
external/ submodule
Git submodule path in each layer repo pinning a tagged release of this pack (ADR-011). (see EXT-02)
contract-check.sh
CI entry that jsonschema-validates every schema and golden fixture before a pin moves. (see EXT-02)
Dual-read
Policy where two schema versions parse in parallel during a consumer rollout (CHANGELOG). (see EXT-05)
Five domains
Energy, Cost, Time/throughput, Continuity/flow, Exception—framed in ADR-030 and vision 09. (see EXT-04)
Envelope
Standard wrapper record defined under contracts/schemas/envelope/ for all published payloads. (see EXT-03)
Finding
Versioned L3→L4 intelligence contract (finding.json 1.2.0 default, 2.0.0 dual-read). (see EXT-03)
card-proposal
L4→L5 decision intake schema replacing deprecated prescription.json for new emits. (see EXT-03)
Handoff
Cross-repo integration docs under handoff/; subordinate to vision/ADR but authoritative for hop-by-hop wiring. (see EXT-01)
Identity lint
scripts/vision-identity-lint.ps1 fails PRs that reintroduce withdrawn Stamped company framing. (see EXT-04)
