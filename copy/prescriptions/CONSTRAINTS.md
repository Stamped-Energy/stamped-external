# Prescription constraints (agents + decks)

Rules we already use when drafting Rx for clients. Source: [`../../demo-decks/prescriptions-examples.md`](../../demo-decks/prescriptions-examples.md) and [`../client/POSITIONING_AND_NARRATIVE.md`](../client/POSITIONING_AND_NARRATIVE.md).

## What a prescription is

A clear **floor action**: what to do, why the data says so, who owns it, effort and window, and how we check the result. If the first window conflicts with standby capacity or an active order, propose the **next-best slot** (negotiation), not a generic alarm.

**Card front:** plant-floor words. **Flip:** tags, baseline, tariff band for the engineer who asks “how do you know?”

## Do

| Constraint | Do |
| --- | --- |
| No vague actions | “Inspect C2 inlet filter in next low-load window” not “improve compressor efficiency” |
| Honest effort | hours, permits, production sign-off |
| Illustrative ₹ / rupees until locked | label sample ranges; lock at Rx issue for M&V |
| Role + department owners | never orphan “maintenance” |
| Feasibility check | orders, standby capacity, department graph before final Due |
| Evidence on flip | tags, baseline window, tariff band — supervisor can defend |
| Lead with outcomes | load / equipment / prescriptions before “agentic AI” |

## Do not claim

- Vibration PdM / RUL %
- “Fine-tuned for you” before plant connect
- MES scheduling / plant OS / EMS / CMMS / PLC write replacement
- Guaranteed savings without locked M&V baseline
- Fleet metrics we have not measured

## Meeting habit

1. Pick **one load** example and **one equipment** example.  
2. Read the talk track aloud — if it sounds like a spec, skip it.  
3. Walk **action → Why → Owner → Due**, then flip for evidence.  
4. Say figures are **`[illustrative]`** until baseline is locked on their plant.
